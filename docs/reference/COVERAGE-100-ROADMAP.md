# Coverage 100% Roadmap

Issue: [#207](https://github.com/ar27111994/agent-harness/issues/207)

## Current status

`npm run validate:coverage` builds the project, runs the coverage-gated test suite, and regenerates the gap ledger for the intended covered runtime surface. The gate is ratcheted to `100` for statements, branches, functions, and lines, and the gate contract depends on two truth guarantees, both checked by `npm run validate`:

- `.c8rc.json` exclusions cover only non-product outputs (see [Exclusion policy](#exclusion-policy)) — enforced by `scripts/check-coverage-exclusions.mjs`.
- Every product-code `c8 ignore start|stop` block is allowlisted and justified (see [Inline ignore blocks](#inline-ignore-blocks)) — also enforced by `scripts/check-coverage-exclusions.mjs`.

The suite currently registers ~1,978 `test(`/`it(` cases across 158 `src/tests/*.test.ts` files and 12 `scripts/tests/*.test.mjs` files; exact metric totals are regenerated by every `validate:coverage` run and recorded in `coverage/coverage-gaps.md` (kept empty at 100%) and `coverage/lcov.normalized.info`.

The v2.0.0 wave added branch-residual coverage suites for AI enrichment, discovery harvesters, recommendation review/policy/selection, host wiring, install refresh, mirror acquisition, HTTP/preflight utilities, and source-sync helpers. The v2.1.0 wave (issue #451) added mocked-HTTP contract coverage for the previously ignore-hidden live-fetch paths: the ARD registry sync (pagination, cursors, caps, referrals persistence, failure handling), the VS Code Marketplace popularity and category sweeps, the package-registry search delegates, and the official-index per-index cap.

The generated gap ledger is empty: `coverage/coverage-gaps.md` has no uncovered line, function, or branch rows. The checked-in `.c8rc.json` gate is now ratcheted to `100` for statements, branches, functions, and lines. This was reached through source simplification for confirmed dead branches and behavioral coverage for reachable runtime paths, not by broadening runtime exclusions.

## Maintained target

The staged ratchet is complete for the currently covered runtime surface:

1. **Completed: `>=99.5%` across statements, branches, functions, and lines.** This floor was used as the first safe release ratchet once real coverage supported it.
2. **Completed: `>=99.9%` across all four metrics.** The final residual pass made this intermediate target unnecessary as a long-lived gate.
3. **Current gate: `100%` statements, branches, functions, and lines.** Keep this gate unless the covered runtime surface changes in a deliberate, documented way.

Future work should preserve the 100% gate by adding real behavioral tests for new reachable paths, removing genuinely dead defensive branches, or documenting only narrow dispatch/generated exclusions when a file is outside the intended runtime surface.

## Reproducible gap inventory

After running coverage, generate the exact uncovered line/function/branch ledger with:

```bash
npm run test:coverage
npm run coverage:gaps
```

For the normal coverage gate, use:

```bash
npm run validate:coverage
```

`npm run validate:coverage` builds the project, runs `npm run test:coverage`, and refreshes `coverage/coverage-gaps.md` from `coverage/lcov.info` in one command.

The generated gap file is intentionally ignored with the rest of the coverage output. A clean report should keep only the table header and no uncovered rows.

## Exclusion policy

Current `.c8rc.json` exclusions are limited to:

- generated test bundles under `dist/tests/**`
- generated type declarations under `dist/types/**`
- script test helpers under `scripts/tests/**`

These are the ONLY allowed values (`ALLOWED_COVERAGE_EXCLUSIONS` in `scripts/check-coverage-exclusions.mjs`); `validate` fails if any product module is added to the exclude list.

Do not add runtime module exclusions to make the percentage green. If a future file appears impossible to cover cleanly, first classify it as:

1. legitimate dead code to remove,
2. a testability gap requiring dependency injection/refactor,
3. missing regression coverage, or
4. generated/dispatch-only code that belongs in `.c8rc.json` with a documented reason.

## Inline ignore blocks

A small number of product-code `c8 ignore start|stop` blocks remain, each confined to an allowlisted file (`ALLOWED_INLINE_IGNORE_FILES` in `scripts/check-coverage-exclusions.mjs`). `validate` fails when a new `c8 ignore start` block appears in any product file outside this allowlist — the fix is either real tests for the newly reached code or a documented justification added here and to the allowlist.

Remaining blocks and justifications:

| File                                        | Lines    | Justification                                                                                                                                                                                                                                                                          |
| ------------------------------------------- | -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/domains/discovery/semantic-scoring.ts` | ~199–217 | Dynamic `import()` of `@xenova/transformers` — the module only resolves when the optional dependency is installed; the harness intentionally never installs it, so the block/error paths are unreachable in the gate.                                                                  |
| `src/domains/discovery/semantic-scoring.ts` | ~330–337 | `fitLevel` defensive fallback branches on a required `FitLevel` union — unreachable with valid typed values.                                                                                                                                                                           |
| `src/package-registries.ts`                 | ~52–61   | Provably unreachable catch in `searchRegistry`: every adapter's `extractResults` handles null gracefully and `fetchJsonWithGuards` never throws for network/HTTP failures (it returns null); all delegate arms are tested with mocked HTTP (see `package-registry-harvester.test.ts`). |

In addition to these blocks, a handful of one-line `c8 ignore next [N]` markers document single defensive branches (unreachable typed fallbacks, optional-dependency guards, V8 source-map artifacts). Each carries an inline rationale; they are not measured as blocks and are kept deliberately small.

Live-fetch paths that were previously hidden behind whole-function ignore blocks are now covered by real mocked-HTTP contract tests:

- `syncArdRegistrySource` (`source-sync-ard-registry.test.ts`): pagination, cursor resume, per-run page cap, entry cap, trust-signal mapping, referrals persistence, failure handling, malformed payloads, missing endpoints. The rewrite also fixed a real defect: the adapter called `fetchJsonWithGuards` without `allowedOrigins`, so the origin guard rejected every request — the ARD consumer could never sync. It now uses the source-sync fetch layer (`fetchRequiredJson` + `getAllowedOrigins`).
- VS Code Marketplace sweeps (`source-sync-vscode-marketplace.test.ts`): popularity and demand-derived category sweeps, their cursor tracking, resume, and completion.
- Package-registry search delegates (`package-registry-harvester.test.ts`): npm/cargo/nuget/maven/packagist/gem arms with URL-prefix mocks.
- Official-index per-index cap (`official-index-harvester.test.ts`): cap=1 blocks the secondary repo-backed source insertion.

## Completion checklist for closing #207

- `npm run coverage:gaps` reports no uncovered lines, functions, or branches for the intended covered runtime surface.
- `.c8rc.json` thresholds are `100` for statements, branches, functions, and lines.
- Any excluded file is dispatch-only/generated or test/type output, not runtime logic masked to improve percentages.
- `npm run validate:coverage` passes locally and in CI.
- `npm run validate:release` passes after the threshold change.
