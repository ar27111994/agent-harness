## Direction findings (not included in plans above)

These are forward-looking opportunities grounded in codebase evidence. They are not bugs — they are product decisions for the maintainer:

### D1: CLI reference generation (`discover environment-index` infrastructure already exists)

`discover environment-index` is shipped but undocumented (`src/cli.ts:256`). The codebase already has `scripts/maintenance-summary.mjs` and `scripts/maintenance-bot-plan.mjs` — generation scripts are an established pattern here. A `scripts/generate-cli-reference.mjs` that reads the command table from `src/cli.ts` and emits `docs/reference/CLI-REFERENCE.md` would be a one-afternoon project that eliminates the DOCS-03/DOCS-04/DOCS-10 findings permanently.

### D2: Structured machine-readable command output

`recommend report` and `setup doctor` output is human-formatted text. The recommend scoring infrastructure already produces a structured `state/recommendations.json`. A `--json` / `--format=json` flag on the most-used commands (report, doctor, stats) would enable automation pipelines and unlock testable assertions without brittle text matching (see TEST-08).

### D3: Session-intent-aware activation (FUTURE-IMPROVEMENTS.md item 2)

The `SessionIntent` type is defined in `src/types/core.ts` but the data model for session-intent-aware overlays is not yet wired. The demand profile already produces `SessionIntent` signals. A `--intent=frontend|backend|security|...` flag on `activate host` that filters the active asset set to the session-specific subset is one of the highest-ROI features visible in the codebase — it directly reduces context overhead for users with large catalogs.

### D4: Catalog-as-a-service / shareable discovery state

`discover sync` downloads and persists indexed source state locally. Users with similar workspaces repeat the same large network operations. The existing JSONL catalog format and lock-file structure are already stable. A `discover publish` / `discover subscribe` flow (share your catalog snapshot with teammates, pull a pre-built catalog instead of re-syncing) would eliminate the primary time cost of onboarding new workspaces. The infrastructure (JSONL, provenance, lock files) is already there; the missing piece is a distribution layer.
